3 · What Still Needs to Be Built

🚧 restore_docdb_elastic — The Step 3 node above does not exist yet in dr-failover-v2.yaml. The current ecs_app_group path calls UpdatePrereqStack which creates a fresh empty DocDB Elastic cluster (no data). To wire in snapshot restore, two things are needed:

1. New Lambda action restore_docdb_elastic in the dr-failover-v2.yaml inline Lambda — calls docdb-elastic:RestoreClusterFromSnapshot, polls until Status = ACTIVE, then calls update_secrets with the new endpoint.

2. New state machine states inserted after UpdatePrereqStack (and before UpdateAppStacksParallel): RestoreDocDBElastic → WaitDocDBElastic → CheckDocDBElasticStatus → DocDBElasticReady → UpdateSecrets.

The prereq_stack_name input key must also carry the docdb_backup_vault_name and backup_role_arn so the Lambda knows which recovery point to restore.
